执行任务 J（全栈新增功能，在现有获奖级界面与韧性基础上；保持现有功能与设计语言，不破坏既有接口，新增项向后兼容）。
用户新增三个诉求，按重要性排序：

【功能1（最重要）：保证每次调查都能完整跑出结果、绝不因中断就失败】
1) 实现“保证收尾/优雅终止”：无论主链路在哪个阶段（PLAN/COLLECT/ANALYZE/VERIFY/REPORT）、因何种原因无法继续（网络抖动、限流、余额不足、来源抓取失败、证据不足、达到搜索/抓取/预算/时间/验证上限、未预期异常），都必须收敛进入受控的“报告收尾”，基于当时已采集的材料生成一份报告，而不是未受控 FAILED/中断。
2) 报告必须可读且如实标注：
   - 完整度分级（完整 / 较完整 / 部分完整 / 资料不足）；
   - 结论主体按 VERIFIED / PROBABLE / 未验证 分层呈现（Answer-first），每条结论带已有引用；
   - 明确缺口（缺哪些直接证据/限定）与“若要更完整可怎么做”；
   - 资料完全为0时，也要产出一份明确的“未能获取到资料”的说明（含可能原因与重试建议），不得只抛技术错误码。
3) 终态语义：成功收尾的运行记为“已完成（可带保留项/部分完整）”，技术异常不再直接暴露为失败；保证顶层有兜底（catch-all）+ 强制 finalize→report 路径，且收尾本身若再遇瞬时错误要能重试、至少落一份最简报告。
4) 时长档位达到上限时，先完成报告收尾再结束，禁止半途抛错终止。

【功能2：发起调查时可选调查时长】
1) 在“新建调查”弹窗（NewInvestigationModal）中，话题输入下方加时长三选一（分段控件/单选卡片，沿用数字卷宗设计语言，默认“标准”）：
   - 快速（约2-5分钟）：少量高权威来源、聚焦最核心子问题、单轮验证、快速给出要点；
   - 标准（约10分钟）：均衡，即当前默认完整度；
   - 深度（30分钟及以上）：更多来源、多轮交叉验证、放宽上限，结论最完整。
   文案明确“时间越长越完整；快速档优先整理最重要内容”。
2) 后端：创建/启动运行的接口新增 depth（quick/standard/deep）字段，缺省 standard、向后兼容；将 depth 映射到搜索轮次、抓取来源上限、每轮送入材料量、分析/验证迭代次数、阶段预算与时间目标（复用现有 stage_budget/预算机制，不要另起一套）。
3) 三档都必须满足功能1：即使是快速档，也必须在时间/预算到点前完成报告收尾、产出结果。

【功能3：删除历史卷宗】
1) 前端：卷宗列表项（及详情页适当位置）提供“删除卷宗”，点击弹确认对话框，明确“将永久删除该调查及其全部运行、来源、证据、声明、报告记录”，需二次确认；删除后从列表移除并给轻提示。
2) 后端：提供 DELETE 调查接口，级联清理该调查下 runs/steps/sources/snapshots/artifacts/evidence/claims/relations/validation/conflicts/report 等全部关联记录（本地 blob/文件按引用计数清理，无引用才删）；对“正在运行”的调查，禁止直接删除并提示先停止（或要求先取消运行）。删除要幂等、重复删除返回明确结果。

【约束】
- 不改变现有结论/防编造/来源独立性质量门；时长档位只改变“投入规模”，不改变“每条结论的确认标准”。
- 样式数值只用 design token，保持八维品质与 prefers-reduced-motion、focus、响应式；不引重型框架。
- 前端集中样式、不改业务 composables 的既有逻辑（仅按需新增）。

【验证与交付】
1) 后端补测试：depth 字段与预算/迭代映射；保证收尾（分别模拟 PLAN/COLLECT/ANALYZE/VERIFY 各阶段失败、持续网络错误、余额不足、0来源，断言都能产出报告且完整度标注正确、无未受控FAILED）；删除级联（关联数据全部清理、运行中禁止删除、幂等）。独立 --basetemp、-p no:cacheprovider 跑全量后端测试、Ruff、导入检查、git diff --check。
2) 前端：npm run build（退出码0）、npm test；用 Playwright 验证时长选择交互、删除二次确认、各档与各主题/各尺寸下无溢出、reduced-motion 正常。
3) 真实 E2E：跑一次 quick 档，确认能在约2-5分钟内完整产出报告（不中断、不失败，含Answer-first结论与缺口说明）；如时间允许再确认 standard 档。
