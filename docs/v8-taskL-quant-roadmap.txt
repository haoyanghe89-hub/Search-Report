任务 L：产出《AI 量化投研 Agent 完整演进方案》。本轮只做规划与可行性调研，禁止改动业务代码（可只读代码、可做数据源/依赖的最小连通性 spike 验证可行性，但不提交业务改动、不重构）。

【现有基线（先读代码核实，不要凭空假设）】
项目 D:\deepsearch（Search-Report）当前是“可验证的联网研究 Agent”，已具备：多后端联网搜索与网页抓取（含退避/熔断/SSRF/正文提取）、候选声明抽取、来源分组与来源族独立性、ENTAILS 语义验证与质量校准、分阶段模型路由与调用韧性、阶段预算与时长三档（quick/standard/deep）、任意中断必优雅收尾并持久化报告、数字卷宗式可追溯报告（结论速览→证据基础→局限与建议→折叠附录）、卷宗删除。技术栈：Python/FastAPI + SQLAlchemy/SQLite + Vue3/Vite，模型走 DeepSeek（OpenAI 兼容）。

【目标】演进为“AI 量化投研 Agent”：用户提出投研问题/假设（如“某标的当前估值与基本面是否匹配”“某因子在A股是否有效”“某策略近三年表现与风险”），Agent 自动取数、做量化计算与可复现验证、交叉核对，并产出带图表、可追溯、可复现的投研报告。市场以 A股为主，兼顾港股/美股（在方案中说明差异与数据源）。

【方案必须覆盖（逐条落地，拒绝空泛宏观）】
1. 现状复用盘点：逐模块列出可直接复用 / 需改造 / 需新建（对应到现有包与文件）。重点说明现有“假设→检索→声明→证据→独立性/语义验证→数字卷宗→报告”的编排如何平移到投研。
2. 目标能力分层：数据层（行情/财务/公告研报/新闻舆情/另类）、投研计算（收益、波动、回撤、夏普/索提诺、Beta、相关性、估值与技术指标）、因子与策略（单因子 IC/IR、分层、多因子合成）、回测引擎（向量化与事件驱动取舍、成本/滑点/印花税/涨跌停/停牌/分红送转/复权）、组合与风险（仓位、行业/风格中性、风险模型、归因、止损与敞口）、Agent 编排、可视化与投研报告。
3. 数据源选型与合规：给出具体数据源对比表——AkShare/Tushare/baostock/yfinance/Ploygon/Alpha Vantage/Sina-EM 等，覆盖市场、免费额度/积分、是否需注册、字段与口径、更新频率、授权与商用边界、稳定性；明确推荐的起步组合与备选/降级链。说明复权、财报发布时点（PIT）、幸存者偏差、停牌退市等数据口径处理。
4. 存储设计：行情/财务的时序与列式存储（parquet/SQLite/DuckDB 取舍）、数据缓存与版本、PIT 数据快照如何纳入卷宗保证可复现；给出数据模型草图。
5. 新增模块与接口设计：到包/文件级的模块划分、关键类与函数签名草图、Agent 可调用的“量化工具”清单（取数、指标、回测、出图），以及与现有 pipeline/验证/报告模块的集成点；HTTP 接口如何增量扩展（保持向后兼容）。
6. Agent 编排与验证范式：把投研结论当作“需验证声明”，证据从“网页引文”扩展为“数据快照 + 可复现计算/回测结果 + 口径说明”；定义量化结论的验证/可信度规则（样本区间、统计显著性、稳健性、避免过拟合与未来函数），且不放松防编造与可追溯底线。
7. 可视化与报告：净值/回撤/持仓/因子分层/相关性/归因等图表方案与前端呈现（沿用数字卷宗设计语言、token、响应式、reduced-motion），投研报告模板（结论速览→数据与口径→分析→回测/因子证据→风险与归因→局限与后续→附录）。
8. 分阶段路线图（高可行性核心）：至少给出
   - P0/MVP：能对单标的自动取数、算核心指标与估值、结合新闻/公告做“投研问答 + 一页投研报告（含图表）”；
   - P1：多标的/横向对比 + 单因子检验与简单策略回测；
   - P2：多因子/组合构建与风险归因；
   - P3：增强（实时/盯盘、更多另类数据、模型优化等）。
   每阶段写明：范围、新增依赖、需改动/新增的模块与文件、验收标准（可执行的测试/演示用例）、工作量粗估（人日量级）、关键风险与回退方案。
9. 风险与陷阱清单：未来函数/前视偏差、幸存者偏差、过拟合与数据窥探、样本外、交易成本与冲击、停牌涨跌停、数据授权合规、密钥与成本、数据源不稳定；给出对应工程防护。
10. 可行性结论与建议：明确“最小可行起步”具体做什么、推荐技术栈与依赖清单（库+建议版本+与现有栈契合度+许可证），以及哪些部分不建议自研（优先用成熟库）。
