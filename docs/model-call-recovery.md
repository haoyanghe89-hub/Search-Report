# 模型调用恢复与费用策略

恢复的验收目标是复用已落盘结果，单独识别执行结果不明的调用，不能承诺严格不重复计费。供应商已完成并计费、但本地保存响应前崩溃时，没有供应商幂等或结果查询能力就无法判断最终费用。

`BoundExternalCalls` 在实际调用模型前，将 `MODEL_CALL_INTENT` 写入现有审计表，并在同一事务中预留一次模型调用预算，不新增持久化表。日志记录运行、逻辑步骤、调用位置、请求指纹和尝试编号。调用位置仍由 harness 的步骤所有权机制保护；同一位置和尝试使用确定性 intent ID，竞争提交会失败，不会同时派发两次。

恢复时的规则：

1. 优先复用校验通过的完整成功录制。即使成功录制后、建立调用绑定前崩溃，也不再次调用供应商。
2. 有 intent 但无对应终态录制，或记录了超时、取消、供应商/传输错误时，按结果不明处理，默认抛出 `MODEL_CALL_OUTCOME_UNKNOWN`，阻止自动重试。intent 的 `OUTCOME_PENDING` 表示派发保留；是否完成以对应录制为准，不能仅凭该字段断言供应商成功或失败。
3. 完整记录的无效结构化响应（含截断）仍允许现有修复流程继续。限流和安全拒绝按原失败策略处理。恢复保护并不保证这些已知响应没有收费。
4. 经运营人员核对供应商日志/账单后，如明确接受可能重复费用，可在该次 `BoundExternalCalls.model` 调用传入 `retry_unknown_outcome=True`。这不是默认全局配置，也没有自动重试开关；新 intent 记录 `ALLOW_POSSIBLE_DUPLICATE_CHARGE`、原未知 intent ID，再占用一次模型调用预算。未记录的第一次 token 用量保持未知，不能虚构为零费用或视为退款。
5. REPLAY 在缺少匹配版本/请求录制时直接失败。即使提供 LIVE 适配器和显式未知结果重试参数，也不会联网补齐。新检索策略须另开 LIVE/录制运行验证。

这一机制仅保护经 harness 绑定的模型调用；旧运行在升级前没有派发 intent 的历史缺口无法事后恢复，搜索和抓取接口也没有新增同等派发日志。它不替代供应商侧幂等、费用查询或运行费用上限。

新 LIVE 的模型客户端关闭 SDK 内部自动重试，避免一次已记账的逻辑调用在传输错误后
隐式再次派发。已知无效响应的结构化修复仍作为独立调用记录；抓取的重试配置保持原样。

## 同一 LIVE 运行继续执行（v4）

新建 LIVE 使用 `resumable-retrieval-v4`。中断、取消、可重试失败，以及因预算耗尽停止的运行，
可以在运行详情的“继续原调查”区域检查并恢复。运行编号、已落盘证据、调用记录、报告历史和
已用预算保留；服务器重启先标记中断；默认在通过安全检查后自动继续，无需手动点击。未知调用、预算耗尽和人工取消仍不会自动重试，详见 [自动恢复说明](automatic-recovery.md)。

- 先调用 `GET /api/runs/{run_id}/recovery`，返回是否可恢复、具体原因、状态版本、剩余预算所需的
  原始计数，以及结果不明的调用清单。旧工作流、回放模式、执行配置改变、缺失或损坏的检查点
  均拒绝恢复。旧版本使用对应版本处理，不能靠修改版本字段升级历史记录。
- 再调用 `POST /api/runs/{run_id}/resume`，提交刚读取的 `expected_state_version`、
  `retry_unknown_intent_ids` 和可选 `budget_increase`。清单中的每个未知 intent 必须明确确认；
  同意一次重试不覆盖后续新产生的未知结果。前端默认不勾选任何确认项。
- 追加预算只提高原运行上限，不能清零用量。支持 `search_calls`、`fetch_calls`、`model_calls`、
  `tokens`、`wall_time_ms`、`sources`、`research_rounds`；省略或填 0 不追加。时间在界面输入分钟，
  API 使用毫秒。累计上限分别为 1000、2000、2000、1000 万、720 万毫秒、2000、20。
- 状态检查、追加预算、写入恢复审计记录在同一事务中完成。重复提交或过期状态返回 409；
  客户端重新读取状态，不自动重试追加额度。充值式增加预算并不等同于供应商账单额度控制。
- `STEP_INPUT_SAVED` 审计事件引用不可变内容寻址 Blob，保存步骤首次输入、结构版本及哈希。
  恢复沿用原输入和验证分批规模，避免已用预算变化导致请求指纹变化。轮次基线、信息增益与
  连续无进展判断也保留。报告阶段的终态在步骤提交时记录，报告生成中断可在本地继续。
- 模型、提供商地址、提示版本及执行策略改变时拒绝恢复；凭据更新和显式增加预算允许。
  已失败的不可重试结构化输出不通过恢复接口无限重试。实质证据缺口不会因追加预算被清除；
  只关闭本次预算暂停生成的具体停止标记。

请求示例（所有 ID 与状态版本必须来自本次 GET 结果，示例不是可直接套用的授权）：

```json
{
  "expected_state_version": 12,
  "retry_unknown_intent_ids": [],
  "budget_increase": {"model_calls": 20, "wall_time_ms": 600000, "research_rounds": 1}
}
```

恢复依赖同一数据库和完整 Blob 卷。保持单个 API worker；此版本没有新增分布式任务队列、
多服务节点恢复协调、供应商幂等或自动账单对账。强制进程终止时，最后一次心跳后未落盘的执行
时间可能无法精确恢复；未知调用的 token/费用也不能当成零。搜索和抓取会复用已有成功录制，
但不具有模型 intent 的未知费用确认机制。所有恢复测试使用离线注入端口，不证明真实供应商
具有 exactly-once 保证。

## 本轮验证（2026-09-30）

- 全量离线后端：323 passed，1 skipped（Windows 非特权符号链接），7 deselected（真实联网/外部基础设施）。
- 新增恢复集成测试 16 项：四个模型阶段的响应落盘后中断、服务重建、取消、逐 intent 确认、
  状态过期与预算追加去重、轮次耗尽、旧版本/回放/配置改变、检查点损坏、报告恢复、无进展历史。
- 前端：25 项测试通过；生产构建通过。
- Ruff check/变更 Python 文件格式检查、mypy（143 个源文件）通过。
- 没有为本轮测试调用真实搜索或模型供应商，未验证真实联网质量或实际费用。
